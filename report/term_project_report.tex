\begin{abstract}
In this project, we introduce the design and implementation of a simple functional programming language with a type system for secure information flow. Building on the simply-typed lambda calculus (STLC), we extend the type system with a graded modality over a security semiring. Inspired by \textit{Graded Modal Dependent Type Theory} \cite{moon2021graded}, our system is intended to prevent unauthorized flows of sensitive data into public outputs and to establish noninterference \cite{smith2007principles} for the core calculus.
\end{abstract}

\begin{IEEEkeywords}
Computer security, information flow, noninterference, security-type systems
\end{IEEEkeywords}

\section{Introduction}

Modern software often handles sensitive data that must remain confidential. The \emph{informational flow control} (or IFC) aims to ensure that high-security inputs of the program do not improperly influence low-security outputs. For example, private user information like passwords should never be leaked to public logs. Formally, the security policy of \emph{noninterference} requires that variations in high-security inputs have no observable effect on low-security outputs. Formally, this requires that variations in high-security inputs result in no observable difference in what an outside observer at low level sees. Violating the IFC principle can lead to information leak, so enforcing noninterference is critical for system security.

\emph{Type systems} \cite{sabelfeld2003language} \cite{abadi1999core} have been proved effective at enforcing noninterference: they associate each value with a \emph{security label} and constrain operations so that a well-typed program is guaranteed not to leak high-security information. For example, consider the following function:

\begin{equation}
	\text{foo}=\lam{x:\nat}{\lam{y:\nat}{x}}
\end{equation}

Then such coeffect systems might allow the function to be typed as
\begin{equation}
	\text{foo}:\nat^\secret\to\nat^\public\to\nat^\secret
\end{equation}
where the first parameter is marked as a high-security input, and the second parameter is marked as a low-security input. If a low-security result depends on a high-security input, the type system would reject the program. Thus, those security type systems can automatically verify that programs adhere to confidentiality policies.

However, existing IFC type systems can be rather inflexible or coarse-grained. Many systems treat security labels in a rigid, lattice-based way \cite{denning1976lattice}, and they can be difficult to combine with other sophisticated type-system constructs. To address these issues, we propose \textsc{FlowSTLC}, a more flexible and extensible type system that tracks informational flows with \emph{graded modalities}. More specifically, we design a simply typed lambda calculus with integrated \emph{graded necessity} for the semiring $\{\public\sqsubseteq\secret\}$, where $\public$ represents low-security information and $\secret$ represents high-security information. This system lets us control how values interact using \emph{coeffects} \cite{petricek2013coeffects} \cite{petricek2014coeffects}, while remaining easy to extend with other program-reasoning constructs such as \emph{usage analysis} \cite{orchard2019quantitative}.

\section{\textsc{FlowSTLC}: The Core Calculus}
\subsection{Syntax}

The \textsc{FlowSTLC} is a graded extension to the simply typed lambda-calculus resembling the Fuzz type system of Reed et al. \cite{reeddistance}. It is also similar to coeffect calculi of Brunel et al. \cite{brunel2014core} and Gaboardi et al. \cite{gaboardi2016combining}.

The syntax of \textsc{FlowSTLC} is a direct extension of STLC with two additional constructs for introducing and eliminating the graded necessity type $\gradedt{\ell}{T}$. We also add records, built-in boolean, natural numbers, and unit type to it:

\begin{figure}[H]
	\centering
	$$
	\begin{aligned}
		\textsf{Term}\;t\;&::=&\;x\;|\;t\; t\;|\;\lambda x.t\;|\;[t]\;|\;\textbf{let }[x]=t\textbf{ in }t\\
		&&\{l_i=t_i^{i\in1..n}\}\;|\;t.l\\
		&&\true\;|\;\false\;|\;\cond{t}{t}{t}\;|\; n\\
		&&\suc{t}\;|\;\prd{t}\;|\;\iszero{t}\;|\;\unt\;|\;\une{t}{t}\\
		\textsf{Type}\;T\;&::=&\;T\to^\ell T\;|\;\square_r T\\
		&&\{l_i:T_i^{i\in1..n}\}\;|\;\untt\;|\;\bool\;|\;\nat\\
	\end{aligned}
	$$
	\caption{Syntax of \textsc{FlowSTLC}}
\end{figure}

The syntax $[t]$ promotes a term to a graded modality, and $\unp{x}{t_1}{t_2}$ eliminates the modality by checking whether $t_2$ uses the unboxed value at its grade and then substituting it into $t_2$. The function type $T\to^\ell T$ records how the function uses its argument. The graded modality $\gradedt{\ell}{T}$ is parameterized by a security grade $\ell$ from the semiring $\secure=\public\sqsubseteq\secret$. Records, projections, booleans, natural numbers, and unit are standard extensions.

Typing judgements are of the regular form $\Gamma\vdash t:T$ with the typing contexts of the form:
$$
\textsf{Context}\;\Gamma\;::=\;\emptyset\;|\;\Gamma,x:[T]_\ell
$$

Contexts are either empty $\emptyset$, or can be extended with  a \emph{graded assumption} $x:[T]_\ell$. For graded assumptions, their grades $\ell$ capture their substructural behavior by describing how can they be used in a term, in this case, the grade capture the security level of information. We will use $dom(\Gamma)$ to denote the variables assigned by context $\Gamma$.

\subsection{Typing}

\textsc{FlowSTLC} has all three standard typing rules of STLC:
\begin{figure}[H]
	\centering
	\begin{prooftree}
		\AXC{}
		\RightLabel{\textsc{T-Var}}
		\UIC{$\srzero\cdot\Gamma,x:[T]_\srone\vdash x:T$}
	\end{prooftree}
	
	\begin{prooftree}
		\AXC{$\Gamma,x:[T_1]_\ell\vdash t:T_2$}
		\RightLabel{\textsc{T-Abs}}
		\UIC{$\Gamma\vdash\lam{x:T_1}{t}:T_1\to^\ell T_2$}
	\end{prooftree}
	
	\begin{prooftree}
		\AXC{$\Gamma_1\vdash t_1:T_{11}\to^\ell T_{12}$}
		\AXC{$\Gamma_2\vdash t_2:T_{11}$}
		\RightLabel{\textsc{T-App}}
		\BIC{$\Gamma_1+\ell\cdot\Gamma_2\vdash t_1\; t_2:T_{12}$}
	\end{prooftree}
	\caption{STLC rules in \textsc{FlowSTLC}}
\end{figure}

The exchange and weakening rules that permit context permutation and expansion are implicit here; permutation is recorded by a separate lemma (see \hyperref[lem-perm]{Permutation lemma}). The differences from standard STLC are that these rules integrate grades into their premises and conclusions. For example, \textsc{T-Var} enforces that all unused assumptions have grade $\secret$, while \textsc{T-Abs} records the usage grade of its bound variable in the arrow type. In \textsc{T-App}, context concatenation combines graded assumptions by semiring addition (see \hyperref[def-concat]{Appendix A.3}).

The next three rules build the structure of the security label semiring:
\begin{figure}[H]
	\centering
	\begin{prooftree}
		\AXC{$\Gamma\vdash t:T$}
		\RightLabel{\textsc{T-Pro}}
		\UIC{$\ell\cdot\Gamma\vdash[t]:\gradedt{\ell}{T}$}
	\end{prooftree}
	
	\begin{prooftree}
		\AXC{$\Gamma_1\vdash t_1:\gradedt{\ell}{T_1}$}
		\AXC{$\Gamma_2,x:[T_1]_\ell\vdash t_2:T_2$}
		\RightLabel{\textsc{T-Let}}
		\BIC{$\Gamma_1+\Gamma_2\vdash\unp{x}{t_1}{t_2}:T_2$}
	\end{prooftree}
	
	\begin{prooftree}
		\AXC{$\Gamma,x:[T_2]_{\ell_1}\vdash t:T_1$}
		\AXC{$\ell_2\sqsubseteq\ell_1$}
		\RightLabel{\textsc{T-Approx}}
		\BIC{$\Gamma,x:[T_2]_{\ell_2}\vdash t:T_1$}
	\end{prooftree}
	\caption{Grade Rules in \textsc{FlowSTLC}}
\end{figure}

The \emph{promotion} rule \textsc{T-Pro} \textquotedblleft promotes\textquotedblright a regular term $t$ to a graded modality by propagating its resource requirement to the context by a \emph{scalar multiplication} (for complete definition of scalar multiplication, see the \hyperref[def-mul]{Appendix A.3}). The \textsc{T-Let} rule provides a way to eliminate graded modality via substitution, where graded value is \textquotedblleft unboxed\textquotedblright and substituted into a graded assumption with matching grades. The context concatenation is also used in the conclusion. Finally, the \emph{approximation} rule \textsc{T-Approx} permits a derivation under grade $\ell_1$ to be used under the lower grade $\ell_2$ when $\ell_2\sqsubseteq\ell_1$. For the security instantiation in this report, this orientation is essential: the reverse direction would make the rejected secret-flow example typable.

The rules for record and projection are based on the book of Pierce and Benjamin \cite{pierce2002types}. Since \textsc{FlowSTLC} has a simply-typed base, there are no subtyping rules for record types:

\begin{figure}[H]
	\centering
	\begin{prooftree}
		\AXC{for each $i$, $\Gamma_i\vdash t_i:T_i$}
		\RightLabel{\textsc{T-Record}}
		\UIC{$\sum_{i=1}^n\Gamma_i\vdash\{l_i=t_i^{i\in 1..n}\}:\{l_i:T_i^{i\in 1..n}\}$}
	\end{prooftree}
	
	\begin{prooftree}
		\AXC{$\Gamma\vdash t:\{l_i:T_i^{i\in 1..n}\}$}
		\RightLabel{\textsc{T-Proj}}
		\UIC{$\Gamma\vdash t.l_i:T_i$}
	\end{prooftree}
	\caption{Record Rules in \textsc{FlowSTLC}}
\end{figure}

The remaining rules specify the types of booleans, natural numbers, unit values, and conditionals, etc.

\begin{figure}[H]

A noteworthy point of these rules is the premise $\ell\sqsubseteq 1$ of rule \textsc{T-Cond}. This requirement is added to prevent the \emph{control flow attack} via \emph{implicit flow}, in which the attacker uses some form of equality checking and control flow to leak information. For example, the following typing derivation is invalid in our system:

\begin{prooftree}
	\def\defaultHypSeparation{\hskip .03in}
	\AXC{$x:[\bool]_\public\vdash x:\bool$}
	\AXC{$\vdash 0:\nat$}
	\AXC{$\vdash 42:\nat$}
	\AXC{$\secret\sqsubseteq\srone$}
	\QuaternaryInfC{$x:[\bool]_\secret\vdash\cond{x}{0}{42}:\nat$}
\end{prooftree}

This is the same solution in Abel and Bernardy \cite{abel2020unified} and Choudhury et al. \cite{choudhury2021graded}.

\subsection{Graded Modality}

The central innovation of \textsc{FlowSTLC} is the use of a graded modality $\gradedt{\ell}{T}$ to track and control information flow. This modality is parameterized by a security grade $\ell$ drawn from the semiring $\secure$, where the ordering signifies that $\secret$ information is more sensitive than $\public$.

Intuitively, a term of type $\gradedt{\ell}{T}$ is a value that should be used according to some security policies, the grade $\ell$ attached to the modality serves as a security constraint: it specifies the minimum security level of the context necessary to eliminate the modality and access the underlying value.

The utility of this approach stems from the algebraic structure of the security semiring. The semiring operations (meet for addition, join for multiplication) naturally model the combination of security constraints:

\begin{itemize}
	\item \textbf{Context Concatenation} uses semiring addition, the meet operation ($\sqcap$), to combine graded assumptions for the same variable. For example, using a variable in two different parts of a program, one requiring $\secret$ and the other $\public$, results in a combined requirement of $\public$ ($\secret\sqcap\public = \public$).
	
	\item \textbf{Context Scalar Multiplication} uses semiring multiplication, the join operation ($\sqcup$), to strengthen the security requirements of a context. This is crucial in the \textsc{T-Pro} rule for ensuring that a promoted term does not leak its contents to a lower grade.
\end{itemize}

Fundamentally, the graded modality $\gradedt{\ell}{T}$ serves as a security-aware container. The typing rules enforce the intended discipline that the "capability" $\ell$ needed to open this container is respected; the noninterference theorem below makes the resulting guarantee precise for the core calculus.

\subsection{A Simple Example}

We demonstrate the system's capability of enforcing noninterference by showing that it rejects the following program:
$$
\lam{x:\gradedt{\secret}{T}}{\textbf{let }[y]=x\textbf{ in }y}:\gradedt{\secret}{T}\to^\public T
$$

as it attempts to use a $\secret$ value to compute a $\public$ value. To type this term, we first need to show that
$$
x:[\gradedt{\secret}{T}]_\public\vdash \textbf{let }[y]=x\textbf{ in }y:\gradedt{\secret}{T}\to^\public T
$$

then according to the premises of \textsc{T-Let} rule, we need to show the following
\begin{enumerate}
	\item $x:[\gradedt{\secret}{T}]_\public\vdash x:\gradedt{\secret}{T}$ 
	\item $y:[T]_\secret\vdash y:T$
\end{enumerate}

Property (1) is immediate, but there is no rule that allows the derivation of (2). The \textsc{T-Var} rule is inapplicable in this context because it requires that the used variable must have a $\public$ grade. Consequently, the term is ill-typed.

\section{Metatheory}
\subsection{Type Safety}
\label{lem-perm}
\begin{lemma}[Permutation]
	If $\Gamma\vdash t:T$ and $\Delta$ is a permutation of $\Gamma$, then $\Delta\vdash t:T$ and the derivation depth of the latter is the same as the former.
\end{lemma}
The permutation proof is by induction on the typing derivation. Preservation and progress additionally require the modal substitution, inversion, canonical-forms, and reduction-compatibility lemmas; the appendix records proof sketches and explicitly identifies these obligations.
\begin{lemma}[Well-typed Modal Substitution]
	If $\Gamma_v\vdash v:T_1$ and $\Gamma_b,x:[T_1]_\ell\vdash t_2:T_2$, then $\Gamma_b+\ell\cdot\Gamma_v\vdash[x\mapsto v]t_2:T_2$. In the \textsc{E-Let-Unbox} case, inversion of the canonical-box typing (including any final approximation step) exposes the required scaled context before this substitution is applied. No reduction premise is needed, so the lemma does not presuppose preservation.
\end{lemma}
We state type safety in the standard two-part form:
\begin{theorem}[Type Preservation]\label{thm-preservation}
	If $\Gamma\vdash t:T$ and $t\reduce t'$, then $\Gamma\vdash t':T$.
\end{theorem}
\begin{theorem}[Progress]\label{thm-progress}
	If $\emptyset\vdash t:T$, then either $t$ is a value or there exists $t'$ such that $t\reduce t'$.
\end{theorem}
The preservation proof is an induction on the reduction derivation, using the modal/graded substitution lemma (including context scaling) for \textsc{E-Let-Unbox} and \textsc{E-AppAbs}; the remaining cases use congruence. The progress proof is an induction on typing, using canonical-forms lemmas for functions, boxes, records, and natural numbers. We state these standard inductions but omit their routine case analysis.

\subsection{Strong Normalization}
\label{thm-sn}
\begin{theorem}[Strong Normalization]
	If $t$ is a closed and well-typed \text{FlowSTLC} term, then every reduction sequence from $t$ terminates (that is, $t$ is strongly normalizing).
\end{theorem}
For this recursion-free calculus, the theorem follows by the standard reducibility argument extended with the record, unit, and modal cases; the full induction is omitted here. The termination-insensitive relations below do not by themselves establish normalization, since their expression clauses intentionally do not require termination.

\section{Fundamental Theorems and Noninterference}

We define the type semantics using a logical-relation model following Rajani et al. \cite{rajani2018types}. The key difference from their work is that our calculus uses a coeffect-based analysis rather than an effect-based analysis.

We first define a type-indexed unary relation $\llbracket T\rrbracket_\calv$ for canonical values, together with an expression relation $\llbracket T\rrbracket_\cale$ whose terminating values inhabit type $T$. The relations are formally defined mutually:

\begin{figure}[H]
	\centering
	$$
	\begin{aligned}
		\llbracket T\rrbracket_\cale &= \{t\mid \forall v.\;(t\rightsquigarrow^* v\ \wedge\ v\text{ is a value})\Rightarrow v\in\llbracket T\rrbracket_\calv\}\\
		\llbracket\untt\rrbracket_\calv &= \{ \unt \} \\
		\llbracket\bool\rrbracket_\calv &= \{\true, \false\} \\
		\llbracket\nat\rrbracket_\calv &= \{n \mid n \in \mathbb{N}\} \\
		\llbracket T_1\to^\ell T_2 \rrbracket_\calv &= \{\lambda x.t \mid \forall v.\;v\text{ is a value}\wedge[v]\in\llbracket\gradedt{\ell}{T_1}\rrbracket_\cale\implies\\ &\qquad[x\mapsto v]t\in\llbracket T_2\rrbracket_\cale\} \\
		\llbracket\gradedt{\ell}{T}\rrbracket_\calv &= \{[v] \mid v\in\llbracket T\rrbracket_\calv\}\\
		\bbrac{\{l_i:T_i^{i\in 1..n}\}}_\calv &= \{\{l_i=v_i^{i\in 1..n}\}\mid\forall i.\;v_i\in\bbrac{T_i}_\calv\}\\
		\llbracket\Gamma\rrbracket&=\{\gamma\mid\forall x:[T]_\ell\in\Gamma.\;[\gamma(x)]\in\llbracket\gradedt{\ell}{T}\rrbracket_\cale\}
	\end{aligned}
	$$
	\caption{Unary value, expression, and context relations}
\end{figure}

For the function type $T_1\to^\ell T_2$, the value interpretation contains abstractions whose bodies remain in the result expression relation after substitution of every admissible boxed value. The graded modal value interpretation contains boxes $[v]$ whose underlying value satisfies the relation for $T$. The expression relation requires every terminating reduction to a canonical value in the value relation; it is therefore termination-insensitive. Finally, $\llbracket\Gamma\rrbracket$ relates substitutions pointwise for every graded assumption in $\Gamma$.

We also define a binary relation which captures \emph{indistinguishability} from the perspective of an adversary level $adv\in\secure$. The relation is formally defined by the following figure:

\begin{figure}[H]
	\centering
	\small
	$$
	\begin{aligned}
		\llbracket T\rrbracket^{adv}_\cale &= \{(t_1,t_2)\mid \forall v_1,v_2.\;(t_1\rightsquigarrow^* v_1\wedge t_2\rightsquigarrow^* v_2\wedge v_1,v_2\text{ are values})\Rightarrow\\
		&\qquad\qquad (v_1,v_2)\in\llbracket T\rrbracket^{adv}_\calv\}\\
		\llbracket\untt\rrbracket^{adv}_\calv &= \{(\unt,\unt)\}\\
		\llbracket\bool\rrbracket^{adv}_\calv &= \{(b,b)\mid b\in\{\true,\false\}\}\\
		\llbracket\nat\rrbracket^{adv}_\calv &= \{(n,n)\mid n\in\mathbb N\}\\
		\llbracket T_1\to^\ell T_2\rrbracket^{adv}_\calv &=
		\{(\lambda x.t_1,\lambda x.t_2)\mid\\
		&\quad(\forall v,v'.\;v,v'\text{ are values}\wedge([v],[v'])\in\llbracket \gradedt{\ell}{T_1}\rrbracket^{adv}_\cale\\
		&\qquad\implies ((x\mapsto v)t_1,(x\mapsto v')t_2)\in\llbracket T_2\rrbracket^{adv}_\cale)\\
		&\qquad\wedge(\forall v.\;v\text{ is a value}\wedge[v]\in\llbracket\gradedt{\ell}{T_1}\rrbracket_\cale\implies\\ &\qquad\qquad[x\mapsto v]t_1\in\llbracket T_2\rrbracket_\cale)\\
		&\qquad\wedge(\forall v.\;v\text{ is a value}\wedge[v]\in\llbracket\gradedt{\ell}{T_1}\rrbracket_\cale\implies\\ &\qquad\qquad[x\mapsto v]t_2\in\llbracket T_2\rrbracket_\cale)\}\\
		\llbracket\gradedt{\ell}{T}\rrbracket^{adv}_\calv &= \left\{\begin{aligned}
			&\{([v_1],[v_2])\mid (v_1,v_2)\in\llbracket T\rrbracket^{adv}_\calv\}\\&\quad\ell\le adv,\\
			&\{([v_1],[v_2])\mid v_1\in\llbracket T\rrbracket_\calv\wedge v_2\in\llbracket T\rrbracket_\calv\}\\&\quad\neg(\ell\le adv)
		\end{aligned}\right.\\
		\bbrac{\{l_i:T_i^{i\in 1..n}\}}^{adv}_\calv &= \{(\{l_i=v_i^{i\in 1..n}\},\{l_i=v_i'^{i\in 1..n}\})\mid\\
		&\quad\forall i.\;(v_i,v_i')\in\bbrac{T_i}^{adv}_\calv\}\\
		\llbracket\Gamma\rrbracket^{adv}&=\{(\gamma_1,\gamma_2)\mid\forall x:[T]_\ell\in\Gamma.\\
		&\qquad([\gamma_1(x)],[\gamma_2(x)])\in\llbracket\gradedt{\ell}{T}\rrbracket^{adv}_\cale\}
	\end{aligned}
	$$
	\normalsize
	\caption{Binary value, expression, and context relations}
\end{figure}

The binary relation specified here captures \emph{termination-insensitive noninterference} \cite{volpano1996sound}: it constrains observations when both evaluations terminate, but does not require co-termination. Establishing termination-sensitive noninterference would require an additional co-termination argument and is outside the scope of this work.

For function types, the binary relation quantifies over pairs of related boxed arguments and relates the resulting bodies; the two unary side conditions ensure each abstraction is well typed. For a modality, grades observable by $adv$ require related underlying values, while grades not observable by $adv$ require only unary validity. In the two-point security order, the non-observable case is exactly $adv=\public$ and $\ell=\secret$. Contexts are related pointwise through this modality interpretation.

\subsection{Fundamental Theorems and Noninterference Property}

To formalize the noninterference property for our type system, we need a so-called "fundamental theorem" that connects the syntactic typing with semantic interpretation. We define a unary and a binary version of the theorem for the two types of relations above respectively.

\begin{theorem}[Unary Fundamental Theorem]
    For all well-typed terms $\Gamma\vdash t:T$, if $\gamma\in\llbracket\Gamma\rrbracket$, then $\gamma\; t\in\llbracket T\rrbracket_\cale$, where $\gamma\; t$ denotes capture-avoiding substitution of the terms in the mapping $\gamma$.
\end{theorem}

The theorem states that, if $t$ is a term of type $T$ under a context $\Gamma$, and $\gamma$ is a unary substitution in the interpretation of $\Gamma$, then $\gamma\; t$ is in the unary relation at type $T$. Its proof also uses grade-erasure of the unary context relation: because the unary interpretation of $\square_\ell T$ is independent of $\ell$, the interpretations of contexts that differ only in grades coincide.

However, since the binary relation involves an external observer, we need additional structure to formally specify it. This needed structure is a subclass of semirings which we call \emph{noninterfering semirings}:

\begin{definition}[Noninterfering Semiring]
    A noninterfering semiring $\mathcal R$ is an ordered semiring (the order and both operations are monotone) with the following additional axioms:
    \begin{itemize}
        \item Weak idempotence of multiplication: $r\cdot r\le r$
        \item Antisymmetry: $(r\le s)\wedge(s\le r)\implies r=s$
        \item Multiplicative unit is minimal: $1\le r$
        \item Additive unit is maximal: $r\le 0$
    \end{itemize}
    where $r,s$ are two elements of the semiring $\mathcal R$.
\end{definition}

\begin{proposition}[Properties of Noninterfering Semiring]
    For an ordered noninterfering semiring and elements $r_1,r_2,s$, the following properties hold:
    \begin{itemize}
        \item Decreasing addition: if $r_1\le r_2$, then $r_1+s\le r_2$.
        \item Increasing multiplication: if $r_1\le r_2$, then $r_1\le s\cdot r_2$ and $r_1\le r_2\cdot s$.
    \end{itemize}
    For the security semiring, $1$ is minimal and $0$ is maximal by definition; these extrema are used in the variable and weakening cases.
\end{proposition}

\begin{proposition}[Security Semiring is Noninterfering]
    The induced semiring $\secure$ is noninterfering, with
    \begin{itemize}
        \item Weak idempotence of multiplication follows from idempotence of $\sqcup$.
        \item Antisymmetry follows from the ordering.
        \item Minimality of $1$ and maximality of $0$ follow from the definition of $\secure$.
    \end{itemize}
\end{proposition}

Now we can formally give the binary version of the fundamental theorem. For a general semiring, the statement assumes the context-scaling, context-combination, and reduction-compatibility lemmas needed in the \textsc{T-Pro}, \textsc{T-Let}, record, and conditional cases; these do not follow from the four axioms above alone:

\begin{theorem}[Binary Fundamental Theorem]
    For all well-typed terms $\Gamma\vdash t:T$ in a calculus parameterized by a noninterfering semiring $\mathcal R$ satisfying these compatibility lemmas, if $(\gamma_1,\gamma_2)\in\llbracket\Gamma\rrbracket^{adv}$, then $(\gamma_1\; t,\gamma_2\; t)\in\llbracket T\rrbracket^{adv}_\cale$, where each substitution is capture avoiding.
\end{theorem}

With the fundamental theorem established, we can now state the final theorem of noninterference:

\begin{theorem}[Termination-insensitive noninterference of \textsc{FlowSTLC}]
    For every judgement $x:[T_1]_r\vdash t:\gradedt{adv}{\base}$ with $adv\le r$ and $adv\ne r$, and closed values $\emptyset\vdash v_1:T_1$ and $\emptyset\vdash v_2:T_1$, the pair
    $([x\mapsto v_1]t,[x\mapsto v_2]t)$ belongs to $\llbracket\gradedt{adv}{\base}\rrbracket^{adv}_\cale$. In particular, if both evaluations terminate with $[b_1]$ and $[b_2]$, then $b_1=b_2$. The conclusion is equality of the observable base values, not full $\beta$-equality of the two terms.
\end{theorem}

Appendix B gives proof sketches for the fundamental and noninterference theorems and records the compatibility lemmas required for a complete formal proof.

\section{Bidirectional Type Checking Algorithm}

While the previous sections defined the declarative typing rules, practical implementation requires an algorithmic system. In this section we introduce the bidirectional typing for \textsc{FlowSTLC}. The typing rules are defined by two mutually recursive functions for \emph{checking} and \emph{synthesis}, of the form:

\begin{equation}
    \begin{split}
        (\textit{checking})\quad&\Phi\vdash t\checking T\dashv\Delta\\
        (\textit{synthesis})\quad&\Phi\vdash t\synthesis T\dashv\Delta
    \end{split}
\end{equation}

Here, we follow a similar approach to Hodas \cite{hodas1994logic} and Polakow \cite{polakow2015embedding}. We split the context into two parts:

\begin{itemize}
    \item Type context $\Phi$: maps variables to types, this is the input to the algorithm.
    \item Usage context $\Delta$: records exactly the variables used in $t$ and their computed grades, this is the output of the algorithm.
\end{itemize}

To support the semiring structure of $\secure$, we define the following pointwise operations on the usage context $\Delta$:

\begin{definition}[Operations on Usage Contexts]\leavevmode
    \begin{itemize}
        \item Zero $0$: maps all variables to $\srzero$.
        \item Addition $\Delta_1+\Delta_2$: returns $\Delta$ where $\Delta(x)=\Delta_1(x)+\Delta_2(x)$.
        \item Scaling $r\cdot\Delta$: returns $\Delta$ where $\Delta(x)=r\cdot\Delta_1(x)$.
        \item Joining $\Delta_1\cup\Delta_2$: returns $\Delta$ where $\Delta(x)=\Delta_1(x)\sqcup\Delta_2(x)$.
    \end{itemize}
\end{definition}

Now we introduce the important rules here. For a complete list of the bidirectional typing rules, please refer to appendix. 

The variable rule generates a usage of $\srone$ for the variable used and $\srzero$ for everything else:

\begin{prooftree}
    \AXC{$\Phi(x)=T$}
    \RightLabel{\textsc{BD-Var}}
    \UIC{$\Phi\vdash x\synthesis T\dashv\{x:\srone\}$}
\end{prooftree}

The system transitions from synthesis to checking:

\begin{prooftree}
    \AXC{$\Phi\vdash t\synthesis T_1\dashv\Delta$}
    \AXC{$T_1=T_2$}
    \RightLabel{\textsc{BD-Switch}}
    \BIC{$\Phi\vdash t\checking T_2\dashv\Delta$}
\end{prooftree}

For function abstractions, we check the function body against its return type. The algorithm verifies that the declared grade $r$ is no greater than the usage grade inferred for the bound variable $x$:

\begin{prooftree}
    \AXC{$\Phi,x:T_1\vdash t\checking T_2\dashv\Delta$}
    \AXC{$r\le\Delta(x)$}
    \RightLabel{\textsc{BD-Abs}}
    \BIC{$\Phi\vdash\lam{x:T_1}{t}\checking T_1\to^r T_2\dashv\Delta\setminus\{x\}$}
\end{prooftree}

The function application synthesizes the function type, checks type of the argument, then scales the argument's usage by the function's input grade $r$:

\begin{prooftree}
    \AXC{$\Phi\vdash t_1\synthesis T_1\to^r T_2\dashv\Delta_1$}
    \AXC{$\Phi\vdash t_2\checking T_1\dashv\Delta_2$}
    \RightLabel{\textsc{BD-App}}
    \BIC{$\Phi\vdash t_1\; t_2\synthesis T_2\dashv\Delta_1+(r\cdot\Delta_2)$}
\end{prooftree}

For the graded modalities, the promotion rule scales the entire usage context of the underlying term by $r$:

\begin{prooftree}
    \AXC{$\Phi\vdash t\checking T\dashv\Delta$}
    \RightLabel{\textsc{BD-Pro}}
    \UIC{$\Phi\vdash[t]\checking\gradedt{r}{T}\dashv r\cdot\Delta$}
\end{prooftree}

Modality elimination synthesizes the modality type $\gradedt{r}{T}$ and then checks the body. The rule ensures that the usage of the unboxed variable inside the body fits within the grade $r$ provided by the modality type:

\begin{prooftree}
    \def\defaultHypSeparation{\hskip .0in}
    \AXC{$\Phi\vdash t_1\synthesis\gradedt{r}{T}\dashv\Delta_1$}
    \AXC{$\Phi,x:T\vdash t_2\checking T_2\dashv\Delta_2$}
    \AXC{$r\le\Delta_2(x)$}
    \TIC{$\Phi\vdash\unp{x}{t_1}{t_2}\checking T_2\dashv\Delta_1+(\Delta_2\setminus\{x\})$}
\end{prooftree}

For the conditional, we check the condition and both branches. Their usage contexts are combined by semiring addition, conservatively accounting for the requirements of either execution path. This algorithmic rule is schematic: a sound implementation must also enforce the declarative side condition that the condition's context-scaling grade is at most $\srone$.

\begin{prooftree}
    \def\defaultHypSeparation{\hskip .0in}
    \AXC{$\Phi\vdash t\checking\bool\dashv\Delta_1$}
    \AXC{$\Phi\vdash t_1\checking T\dashv\Delta_2$}
    \AXC{$\Phi\vdash t_2\checking T\dashv\Delta_3$}
    \TIC{$\Phi\vdash\cond{t}{t_1}{t_2}\checking T\dashv\Delta_1+\Delta_2+\Delta_3$}
\end{prooftree}

The bidirectional rules for records, natural numbers, booleans, and unit values are omitted for brevity due to their standard nature.

\subsection{A Bidirectional Typing Example}

Consider the term $f\; z$ with the following typing context $\Phi$:
\begin{itemize}
    \item $f:T\to^\secret T$, and
    \item $z:T$
\end{itemize}
The goal is to synthesize the type and usage context for the application:
\begin{equation}
    \Phi\vdash f\; z\synthesis T\dashv\Delta_{total}
\end{equation}
Since it is an application, we use the \textsc{BD-App} rule first. The rule requires us to synthesize the type for the function $f$ and check the argument $z$ against the function's input type. The former comes from a direct application of the rule \textsc{BD-Var}:
\begin{equation}
    \Phi\vdash f\synthesis T\to^\secret T\dashv\{f:\public,z:\secret\}
\end{equation}
The latter can be achieved by combining the two rules \textsc{BD-Switch} and \textsc{BD-Var}:
\begin{equation}
    \Phi\vdash z\checking T\dashv\{f:\secret,z:\public\}
\end{equation}
Then we combine the two usage contexts using the formula $\Delta_1+r\cdot\Delta_2$, where the function's input grade is $r=\secret$:
\begin{equation}
    \begin{split}
        \Delta_{total}
        &=\{f:\public,z:\secret\}+\secret\cdot\{f:\public,z:\secret\}\\
        &=\{f:\public,z:\secret\}+\{f:\secret\cdot\public,z:\secret\cdot\secret\}\\
        &=\{f:\public,z:\secret\}+\{f:\secret,z:\secret\}\\
        &=\{f:\public+\secret,z:\secret+\secret\}\\
        &=\{f:\public,z:\secret\}\\
    \end{split}
\end{equation}
So the final result is
\begin{equation}
    \Phi\vdash f\; z\synthesis T\dashv\{f:\public,z:\secret\}
\end{equation}
and the typing succeeds.

\section{Implementation}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.6\linewidth]{./flowstlc_interpreter_pipeline.png}
    \caption{\textsc{FlowSTLC} Implementation Pipeline}
\end{figure}

We implemented \textsc{FlowSTLC} as a small interpreter pipeline in Java 17, with syntax defined using ANTLR4\cite{parr2013definitive} and semantics enforced by a typechecker based on the bidirectional typing system developed in the previous section. The front-end is specified by \texttt{FlowSTLCLexer.g4} and \texttt{FlowSTLCParser.g4}, which define a Haskell-like expression language (literals, variables, let/if, sequencing, records, arithmetic/boolean operators) plus explicit security annotations ($\secret$/$\public$) and modalities. Types include built-in base types (booleans, integers, strings, and unit), record types, modality types, and graded function types written \texttt{T1\textasciicircum r -> T2}. The parse tree produced by ANTLR is converted into a small, explicit AST using \texttt{ASTBuilder}, which maps each grammar alternative to a dedicated node (e.g., \texttt{LetExpr}, \texttt{IfExpr}, \texttt{FunctionCallExpr}, \texttt{ModalityExpr}, \texttt{RecordExpr}) and similarly builds the type nodes (\texttt{FunctionType}, \texttt{ModalityType}, \texttt{RecordType}, etc.). This separation lets later phases operate on stable, type-theory-aligned constructs rather than parser artifacts.

The core static semantics is implemented in \texttt{BidirectionalTypeChecker} using two mutually recursive judgments: a synthesis mode and a checking mode. Besides the rules specified in appendix, we also added a few rules to make the language more practical. For example, type checking rules for arithmetic/logical/comparison/(in)equality operators, intrinsic function calls, and sequencing constructs. Type errors are surfaced as \texttt{TypeError} exceptions with human-readable diagnostics.

The dynamic semantics is realized by a straightforward environment-based interpreter (\texttt{EvalVisitor} + \texttt{Interpreter}) over the AST. Top-level constants evaluate to values and functions evaluate to closures capturing their lexical environment; calls extend the closure environment with evaluated arguments, giving standard call-by-value, lexically scoped execution. Importantly, security labels are enforced statically and erased dynamically: \texttt{ModalityExpr} evaluates as a runtime no-op (it simply evaluates its inner expression), matching the intended "filtered label" interpretation where confidentiality is a static property of programs rather than a runtime tag. Intrinsics implement basic I/O at the value level. Finally, we provide a language server (LSP4J) to support interactive development: it reparses documents and reruns the typechecker on edits to publish diagnostics, and implements hover and semantic tokens. Build and packaging are automated via Maven, producing shaded runnable jars for both the CLI compiler driver and the language server entry point.

The project implementation can be found at the GitHub repository \href{https://github.com/nofe1248/cs315-term-project}{nofe1248/cs315-term-project}.

\section{Examples}

This section illustrates the practical application of \textsc{FlowSTLC} through concrete examples of information flow checking.

The first example, adapted from the work on Granule \cite{orchard2019quantitative}, demonstrates the handling of high-security data types.

\begin{lstlisting}[style=mystyle]
val secret : Int [Sec] = [42]

fun hash : Int [Sec]^Pub -> Int [Sec]
fun hash n = let [x] = n in [x * x * x]

fun main : Unit^Pub -> Int [Sec]
fun main = hash secret
\end{lstlisting}

In this listing, the variable \texttt{secret} is defined as a modality with a secret grade. Consequently, the type system restricts operations on this variable to secret-guarded modalities, such as the \texttt{hash} function.

Attempts to modify the signature of the hash function to downgrade the security level results in type errors. For instance, changing the output grade to Pub or removing the modality entirely elicits the following diagnostic:

\begin{lstlisting}[style=mystyle]
// either
fun hash : Int [Sec]^Pub -> Int [Pub]
fun hash n = let [x] = n in [x * x * x]\\
// or
fun hash : Int [Sec]^Pub -> Int
fun hash n = let [x] = n in x * x * x
\end{lstlisting}

\begin{lstlisting}[style=mystyle]
Type checking failed: 
  In let-binding: variable 'x' used at Pub 
  which is not > declared modality grade Sec
\end{lstlisting}

The type checker rejects these programs because they facilitate the flow of secret values into the public domain, which violates the noninterference property.

The second example demonstrates the prevention of control-flow attacks (implicit flows). Consider the following function definitions:

\begin{lstlisting}[style=mystyle]
fun not_leak : Bool^Pub -> Bool
fun not_leak a = if a then false else true

fun cfa : Bool^Sec -> Bool
fun cfa a = if a then false else true
\end{lstlisting}

The function \texttt{not\_leak} is well-typed because the conditional expression depends on a public input. Conversely, the function \texttt{cfa} (Control-Flow Attack) attempts to utilize a secret boolean value within the condition. The type checker detects this violation and rejects the code:

\begin{lstlisting}[style=mystyle]
Type checking failed:
  In cfa: parameter 'a' used at Pub 
  which is not > declared input grade Sec
\end{lstlisting}

To resolve this typing error, the result must be encapsulated within a modality:

\begin{lstlisting}[style=mystyle]
fun not_longer_cfa : Bool^Sec -> Bool [Sec]
fun not_longer_cfa a = [(if a then false else true)]
\end{lstlisting}

Since a secret-graded modality cannot be eliminated in a public context, this revised program conforms to the noninterference property and is accepted by the type system.

\section{Related Work}

Language-based IFC has a rich literature. Sabelfeld and Myers \cite{sabelfeld2003language} survey a variety of security type systems that enforce noninterference via typing. Seminal work by Volpano et al. \cite{volpano1996sound} introduced a static type system for a simple imperative language, ensuring well-typed programs satisfy noninterference. Extensions include JFlow \cite{myers1999jflow} and JIF \cite{pullicino2014jif} for Java, which associate security labels with Java types to track flows, and FlowCaml \cite{simonet2003flow} for OCaml, which similarly adds a security type-checker. Generally, these systems label each variable as high or low and enforce rules so that no operation can use a high value in a low context.

More recently, graded type theories have been proposed to generalize such analyses. Graded type systems annotate types with additional information ("grades") to capture various properties of programs. For example, the Granule language \cite{orchard2019quantitative} uses graded modalities to track the effects and coeffects of program. In information flow use-cases, types are graded by a security lattice, allowing automatic enforcement of noninterference. Moon et al. introduce the Graded Modal Dependent Type Theory (\textsc{GrTT}) \cite{moon2021graded}, which extends dependent type system with graded modality and show that the grades can be effective at reasoning of programs. This work demonstrates that graded modality can capture fine-grained flow policies in types. Similarly, Marshall and Orchard \cite{marshall2023graded} demonstrated a graded-modal framework that can enforce confidentiality and even integrity simultaneously.

Other approaches include dynamic IFC (e.g. the LIO monad in Haskell \cite{stefan2011flexible}) or hybrid systems, but our focus is purely static. Classical security type systems (JIF, FlowCaml, etc.) enforce noninterference via fixed lattice labels. Our project draws on these ideas while adapting graded modalities to a simple functional language to track information flows more flexibly.

\section{Further Work and Conclusion}

In summary, \textsc{FlowSTLC} presents a simple lambda calculus with graded necessity for enforcing secure information flow. By instantiating grades with the security semiring $\secure$, the system tracks data labels at the type level. The stated noninterference result is conditional on the compatibility lemmas listed above; within those assumptions, well-typed core-calculus programs cannot change an observable base result by varying a high-grade input.

While the results are promising, \textsc{FlowSTLC} in its current form is an \emph{idealized model} with clear limitations. For one, the core calculus is deliberately small and omits many practical language features. It includes records and base types, but no algebraic data types, recursive types, polymorphism, or dependent typing. As observed in prior work, static IFC models with minimal features have historically been considered "too limited or too restrictive to be used in practice" \cite{myers1999jflow}. Thus, our model inherits this limitation of expressiveness. Second, \textsc{FlowSTLC} exists only as a theoretical calculus and has not been integrated into a production-ready programming language. We consider that bridging this gap is a non-trivial challenge. For example, a recent survey noted that even in a rich language like Rust, implementing a sound IFC system requires "building an ad-hoc effect tracking system using bleeding-edge features of the Rust compiler". Finally, we have not evaluated performance or conducted real-world case studies. There are no benchmarks on typing or runtime costs, nor have we applied \text{FlowSTLC} to any non-trivial programs. In contrast, systems like JFlow and Cocoon \cite{lamba2024cocoon} have shown that static IFC checking can incur negligible overhead. Without such evaluation, the practical impact of \textsc{FlowSTLC} remains speculative.

Given these limitations, there are many promising directions for future work. We highlight several concrete directions:
\begin{itemize}
    \item \textbf{Extending the type system with dependent types and polymorphism.} One natural extension is to enrich \textsc{FlowSTLC} with more expressive typing disciplines. In particular, adding \emph{dependent types} could allow security policies to depend on program values and thus encode more precise confidentiality and declassification properties. Prior work (e.g. DepSec for Idris language \cite{gregersen2019dependently}) shows that dependent types increase the expressiveness of static IFCs. Similarly, introducing \emph{parametric polymorphism} would permit writing generic secure functions without duplicating code.
    \item \textbf{Combining graded modalities with effect, usage, or resource typing.} Another interesting direction is to study how the security grading interacts with other static analyses. Graded type theories generalize both effect systems (via graded monads) and coeffect/usage systems (via graded comonads). For example, \textsc{FlowSTLC} might be extended with an effect system that tracks side-effects or I/O on secret data (similar to Koka's effect typing system \cite{leijen2014koka} \cite{leijen2016algebraic}). Alternatively, one could explore \emph{coeffect-like} analyses where the context is graded alongside security. Integrating graded security labels with \emph{resource-} or \emph{capability-aware typing} could yield richer guarantees.
    \item \textbf{Embedding \textsc{FlowSTLC} in a practical language or compiler.} To bring theory closer to practice, an implementation of \textsc{FlowSTLC}'s typing discipline in a real programming environment is essential. One approach is to create a domain-specific language (DSL) or library for an existing language (e.g. Haskell or OCaml) that enforces these graded security types. Recent work (e.g. \cite{lamba2024cocoon}) shows that it is possible to add IFC to Rust without modifying the compiler. Similarly, the Granule project \cite{orchard2019quantitative} demonstrates that a language with graded, linear, and dependent types can be realized in practice. Following these examples, we could adapt \textsc{FlowSTLC}'s type checker into an implementation (for instance, a GHC plugin) to test on larger codebases. Such an embedding would enable empirical measurement of type-checking performance and runtime costs. It would also allow exploration of practical issues (language interoperability, tooling integration, etc.) that are vital for any real applications of our outcome.
\end{itemize}

In conclusion, \textsc{FlowSTLC} provides a formal foundation for secure information flow via graded modal types, but many challenges remain. Future work will pursue richer type features, deeper integration with program reasoning (effects, resources), and practical implementation efforts. We are optimistic that bridging these gaps will bring secure flow typing closer to real-world programming. By pursuing these directions, we hope to develop a mature framework that combines the rigorous guarantees of our type-theoretic approach with the expressiveness and practicality needed for deployed systems.

\subsubsection{Security Level Semiring}

\begin{definition}[Security Level Semiring]
The security level semiring $\mathbb{S}$ is a two-point lattice of security levels $\secure=\{\public\sqsubseteq\secret\}$ with 
\begin{itemize}
	\item $\srzero=\secret$
	\item $\srone=\public$
	\item Addition as the meet: $r+s=r\sqcap s$
	\item Multiplication as the join $r\cdot s=r\sqcup s$
\end{itemize}
\end{definition}
See \hyperref[app-b]{Appendix B} for a proof that this algebra is indeed a semiring.

\subsection{Proofs}\label{app-b}
\subsubsection{Security Level Semiring}
\begin{proof}\leavevmode
	\begin{itemize}
		\item \textbf{Associativity of addition}: $(a+b)+c=a+(b+c)$
		
		This is trivial since the semiring addition is meet, which is associative in a lattice.
		\item \textbf{Commutativity of addition}: $a+b=b+a$
		
		This is also trivial since meet is commutative in a lattice.
		\item \textbf{Additive identity}: $a+\srzero=a$ for all $a$
		
		Since $0=\secret$ and $\secret$ is the maximum element of $\secure$, we have
		\begin{equation}
			\begin{aligned}
				\secret\sqcap\secret&=\secret\\
				\public\sqcap\secret&=\public\\	
			\end{aligned}
		\end{equation}
		\item \textbf{Associativity of multiplication}: $(a\cdot b)\cdot c=a\cdot (b\cdot c)$
		
		This is trivial by the associativity of join operation.
		
		\item \textbf{Multiplication distributes over addition}: $a\cdot(b+c)=(a\cdot b)+(a\cdot c)$ and $(a+b)\cdot c=(a\cdot c)+(b\cdot c)$
		
		The distributivity trivially holds since $\secure$ is a two-point lattice.
		
		\item \textbf{Multiplicative identity}: $a\cdot\srone=a$ for all $a$
		
		Since $1=\public$ and $\public\sqsubset\secret$, we have
		\begin{equation}
			\begin{aligned}
				\public\sqcup\public&=\public\\
				\public\sqcup\secret&=\secret\\
			\end{aligned}
		\end{equation}
		\item \textbf{Multiplication by 0 annihilates}: $\srzero\cdot a=a\cdot\srzero=\srzero$ for all $a$
		
		Since $0=\secret$ and $\public\sqsubset\secret$, we have
		\begin{equation}
			\begin{aligned}
				\secret\sqcup\secret&=\secret\\
				\public\sqcup\secret&=\secret\\
			\end{aligned}
		\end{equation}
	\end{itemize}
	Thus the security level algebra is a semiring.
\end{proof}

\subsubsection{Unary Fundamental Theorem}

\begin{proof}
	By induction on the typing derivation of $\Gamma\vdash t:T$
	\begin{itemize}
		\item \emph{Case} \textsc{T-Var}: $\srzero\cdot\Gamma,x:[T]_\srone\vdash x:T$.
		
		Let $\gamma\in\llbracket\srzero\cdot\Gamma,x:[T]_\srone\rrbracket$. The context relation gives $[\gamma(x)]\in\bbrac{\gradedt{\srone}{T}}_\cale$. By the definition of the modality relation (and grade-erasure), this implies $\gamma(x)\in\bbrac{T}_\cale$. Since the term is just $x$, $\gamma\;t=\gamma(x)$, satisfying the goal.
		
		\item \emph{Case} \textsc{T-Abs}: $\Gamma\vdash\lam{x:T_1}{t}:T_1\to^r T_2$ derived from $\Gamma,x:[T_1]_r\vdash t:T_2$.
		
		Assume $\gamma\in\bbrac{\Gamma}$; we must show that $\lam{x:T_1}{t}\in\bbrac{T_1\to^r T_2}_\calv$. Let $v$ be a value with $[v]\in\bbrac{\gradedt{r}{T_1}}_\cale$. Grade-erasure lets us extend $\gamma$ with $x\mapsto v$ to a substitution in $\bbrac{\Gamma,x:[T_1]_r}$. By the induction hypothesis on the premise $\Gamma,x:[T_1]_r\vdash t:T_2$, we obtain $[x\mapsto v]t\in\bbrac{T_2}_\cale$, which is the required function-value condition.
		
		\item \emph{Case} \textsc{T-App}: $\Gamma_1+r\cdot\Gamma_2\vdash t_1\; t_2:T_2$.
		
		Assume $\gamma\in\bbrac{\Gamma_1+r\cdot\Gamma_2}$. By the context-combination and grade-erasure lemmas, $\gamma$ satisfies both premise contexts. The induction hypotheses place the function and argument in their respective expression relations. To verify the expression relation, consider any terminating evaluation of the application: call-by-value evaluation then gives terminating evaluations of the function and argument to related values. The function-value clause and the application reduction rule give the result in $\bbrac{T_2}_\cale$; no termination of an arbitrary semantic substitution is assumed.
		
		\item \emph{Case} \textsc{T-Pro}: $r\cdot\Gamma\vdash [t]:\gradedt{r}{T}$.
		
		By the induction hypothesis, $\gamma\; t\in\bbrac{T}_\cale$. Evaluation compatibility gives $[\gamma\;t]\reduce^*[v]$ whenever $\gamma\;t\reduce^*v$ with $v\in\bbrac{T}_\calv$; hence the boxed term is in $\bbrac{\gradedt{r}{T}}_\cale$.
		
		\item \emph{Case} \textsc{T-Let}: $\Gamma_1+\Gamma_2\vdash\unp{x}{t_1}{t_2}:T_2$.
		
		By the induction hypothesis, $\gamma\; t_1\in\bbrac{\gradedt{r}{T_1}}_\cale$. To verify the expression relation, consider any terminating evaluation of the let-term. Call-by-value evaluation then gives $\gamma\;t_1\reduce^*[v]$ with $[v]$ a canonical boxed value and $v\in\bbrac{T_1}_\calv$. Extend $\gamma$ with $x\mapsto v$ and apply the induction hypothesis to $t_2$; the let-elimination step then preserves the expression relation. No termination of an arbitrary semantic substitution is assumed.
		
		\item \emph{Case} \textsc{T-Approx}: $\Gamma,x:[T_1]_s:t:T_2$ where $r\le s$.
		
		The unary relation for $\gradedt{r}{T}$ does not depend on the value of $r$. Thus, if $\gamma(x)\in\bbrac{\gradedt{s}{T_1}}_\cale$, it is also in $\bbrac{\gradedt{r}{T_1}}_\cale$. The induction hypothesis applies directly.
		
		\item \emph{Case} \textsc{T-Record}: $\sum_i\Gamma_i\vdash\{l_i=t_i^{i\in 1..n}\}:\{l_i:T_i^{i\in 1..n}\}$.
		
		By context-combination compatibility, $\gamma$ satisfies each field context $\Gamma_i$. The induction hypothesis therefore gives $\gamma\; t_i\in\bbrac{T_i}_\cale$ for every $i$; any terminating record has fields in the corresponding value relations, so it belongs to $\bbrac{\{l_i:T_i^{i\in 1..n}\}}_\cale$.
		
		\item \emph{Case} \textsc{T-Proj}: $\Gamma\vdash t.l_i:T_i$.
		
		By the induction hypothesis, every terminating evaluation of $\gamma\;t$ yields a record $\{l_i=v_i^{i\in 1..n}\}$ with $v_i\in\bbrac{T_i}_\calv$. The projection rule then yields $\gamma\;(t.l_i)\in\bbrac{T_i}_\cale$.
		
		\item \emph{Case} \textsc{T-True}: $\srzero\cdot\Gamma\vdash\true:\bool$.
		
		This follows immediately from the definition $\true\in\bbrac{\bool}_\calv$.
		
		\item \emph{Case} \textsc{T-False}: $\srzero\cdot\Gamma\vdash\false:\bool$.
		
		This follows immediately from the definition $\false\in\bbrac{\bool}_\calv$.
		
		\item \emph{Case} \textsc{T-Cond}: $r\cdot\Gamma_1+\Gamma_2+\Gamma_3\vdash\cond{t_1}{t_2}{t_3}:T_1$.
		
		By context-combination compatibility, $\gamma$ satisfies each premise context. The induction hypothesis gives $\gamma\;t_1\in\bbrac{\bool}_\cale$. If it evaluates to $\true$ (respectively, $\false$), the corresponding branch evaluates in $\bbrac{T_1}_\cale$ by the induction hypothesis, and the conditional evaluation preserves that relation.
		
		\item \emph{Case} \textsc{T-Zero}: $\srzero\cdot\Gamma\vdash 0:\nat$.
		
		This follows immediately from the definition $0\in\bbrac{\nat}_\calv$.
		
		\item \emph{Case} \textsc{T-Succ}: $\Gamma\vdash\suc{t}:\nat$.
		
		By the induction hypothesis and the successor rule, the result reduces to the canonical numeral $n+1$, which is in $\bbrac{\nat}_\calv$.
		
		\item \emph{Case} \textsc{T-Pred}: $\Gamma\vdash\prd{t}:\nat$.
		
		By the induction hypothesis and the predecessor rules, the term reduces to a canonical numeral (either $0$ or $n$), hence belongs to $\bbrac{\nat}_\cale$.
		
		\item \emph{Case} \textsc{T-IsZero}: $\Gamma\vdash\iszero{t}:\bool$.
		
		By the induction hypothesis and the zero-test rules, the term reduces to either $\true$ or $\false$, both of which are in $\bbrac{\bool}_\calv$.
		
		\item \emph{Case} \textsc{T-Unit}: $\srzero\cdot\Gamma\vdash\unt:\untt$.
		
		This follows immediately from the definition $\unt\in\bbrac{\untt}_\calv$.
		
		\item \emph{Case} \textsc{T-Unit-Elim}: $\Gamma_1+\Gamma_2\vdash\une{t_1}{t_2}:T_2$.
		
		For any terminating evaluation of the unit-elimination term, call-by-value evaluation first gives $\gamma\;t_1\reduce^*\unt$. The induction hypothesis on $t_2$ then yields the result in $\bbrac{T_2}_\cale$.
	\end{itemize}
\end{proof}

\subsubsection{Binary Fundamental Theorem}

\begin{proof}
	By induction on the typing derivation.
	\begin{itemize}
        \item \emph{Case} \textsc{T-Var}: $\srzero\cdot\Gamma,x:[T]_\srone\vdash x:T$.
        
        The context relation gives the inputs in $\bbrac{\gradedt{\srone}{T}}^{adv}_\cale$. Since $\srone\le adv$ by minimality of $\srone$, this is the observable modality case, which yields related underlying values at $T$.
        
        \item \emph{Case} \textsc{T-Abs}: $\Gamma\vdash\lam{x:T_1}{t}:T_1\to^r T_2$, $\Gamma,x:[T_1]_r\vdash t:T_2$.
        
        For $(u_1,u_2)\in\bbrac{\gradedt{r}{T_1}}^{adv}_\cale$, extend the two related substitutions with the underlying values and apply the induction hypothesis to obtain $([x\mapsto u_1]t,[x\mapsto u_2]t)\in\bbrac{T_2}^{adv}_\cale$, which is the function-value condition.
        
        \item \emph{Case} \textsc{T-App}: $\Gamma_1+r\cdot\Gamma_2\vdash t_1\; t_2:T_2$.
        
        By the induction hypotheses and the context-combination/scaling lemmas, the function and argument pairs are in their respective expression relations. Reduction compatibility lifts the argument relation to the required pair of boxed values, and the binary function-value clause yields the result in $\bbrac{T_2}^{adv}_\cale$.
        
        \item \emph{Case} \textsc{T-Pro}: $r\cdot\Gamma\vdash [t]:\gradedt{r}{T}$.
        
        We have 2 subcases to consider:
        \begin{itemize}
            \item \emph{Subcase} $r\le adv$: The required context-relatedness follows from the explicit monotonicity and compatibility lemmas for context scaling; these lemmas must be proved for the chosen semiring (they do not follow from weak idempotence alone). Applying the induction hypothesis then gives the related promoted values.
            \item \emph{Subcase} $\neg(r\le adv)$: both promoted results satisfy the unary relation by the Unary Fundamental Theorem, which is exactly the unobservable branch of the modality relation.
        \end{itemize}
        
        \item \emph{Case} \textsc{T-Let}: $\Gamma_1+\Gamma_2\vdash\unp{x}{t_1}{t_2}:T_2$.
        
        If the eliminated modality has grade $r\le adv$, the unwrapped values are related by the observable case of the modality binary relation, and the induction hypothesis applies to the body. If $\neg(r\le adv)$, the two unwrapped values need only satisfy the unary relation; the body case therefore requires the corresponding non-observability/compatibility lemma for the graded context, rather than any claim about the result type's grade.
        
        \item \emph{Case} \textsc{T-Approx}: $\Gamma,x:[T_1]_s:t:T_2$ where $r\le s$.
        
        The conclusion context has the lower grade $r$, with $r\le s$. Related substitutions at grade $r$ also satisfy the premise context at grade $s$, because the binary modality relation becomes weaker as the grade increases. The induction hypothesis therefore applies to the premise derivation.
        
        \item \emph{Case} \textsc{T-Record}: $\sum_i\Gamma_i\vdash\{l_i=t_i^{i\in 1..n}\}:\{l_i:T_i^{i\in 1..n}\}$.
        
		By context-combination compatibility, both related substitutions satisfy each field context $\Gamma_i$. The induction hypotheses give related field evaluations, and combining them yields $(\{l_i=t_i^{i\in 1..n}\},\{l_i=t_i'^{i\in 1..n}\})\in\bbrac{\{l_i:T_i^{i\in 1..n}\}}^{adv}_\cale$.
        
        \item \emph{Case} \textsc{T-Proj}: $\Gamma\vdash t.l_i:T_i$.
        
        By the induction hypothesis, both scrutinees reduce to related record values. Reduction compatibility and the projection closure lemma then imply that their projections are related at $T_i$; no syntactic equality of the two records is required.
        
        \item \emph{Case} \textsc{T-True}: $\srzero\cdot\Gamma\vdash\true:\bool$.
        
        This follows immediately from the definition $(\true,\true)\in\bbrac{\bool}^{adv}_\calv$.
        
        \item \emph{Case} \textsc{T-False}: $\srzero\cdot\Gamma\vdash\false:\bool$.
        
        This follows immediately from the definition $(\false,\false)\in\bbrac{\bool}^{adv}_\calv$.
        
        \item \emph{Case} \textsc{T-Cond}: $r\cdot\Gamma_1+\Gamma_2+\Gamma_3\vdash\cond{t_1}{t_2}{t_3}:T_1$.
        
        We have two subcases to consider:
        \begin{itemize}
            \item \emph{Subcase} $r\le adv$: Then $\gamma_1\; t_1$ and $\gamma_2\; t_1$ must result in the same boolean value. Thus both execution take the same branch, and the induction hypothesis on the executed branch applies.
            \item \emph{Subcase} $\neg(r\le adv)$: The branches may differ. The result is related only via the unobservable case, using the unary fundamental theorem and the compatibility lemma for conditionals; no result grade is implied by \textsc{T-Cond}.
        \end{itemize}
        
        \item \emph{Case} \textsc{T-Zero}: $\srzero\cdot\Gamma\vdash 0:\nat$.
        
        This follows immediately from the definition $(0,0)\in\bbrac{\nat}^{adv}_\calv$.
        
        \item \emph{Case} \textsc{T-Succ}: $\Gamma\vdash\suc{t}:\nat$.
        
        The two evaluations reduce, by compatibility, to canonical numerals; the numeral relation relates identical canonical forms.
        
        \item \emph{Case} \textsc{T-Pred}: $\Gamma\vdash\prd{t}:\nat$.
        
        The predecessor evaluations reduce to identical canonical numerals, which are related at $\nat$.
        
        \item \emph{Case} \textsc{T-IsZero}: $\Gamma\vdash\iszero{t}:\bool$.
        
        The two zero tests reduce to identical booleans, which are related at $\bool$.
        
        \item \emph{Case} \textsc{T-Unit}: $\srzero\cdot\Gamma\vdash\unt:\untt$.
        
        This follows immediately from the definition $(\unt,\unt)\in\bbrac{\untt}^{adv}_\calv$.
        
        \item \emph{Case} \textsc{T-Unit-Elim}: $\Gamma_1+\Gamma_2\vdash\une{t_1}{t_2}:T_2$.
        
        Follows immediately from the induction hypothesis on the body $t_2$.
    \end{itemize}
\end{proof}

\subsubsection{Noninterference of \textsc{FlowSTLC}}

\begin{proof}
	Because $adv\le r$ and $adv\ne r$, antisymmetry gives $\neg(r\le adv)$. The unary fundamental theorem places each closed input value in $\bbrac{T_1}_\cale$, so the pair of substitutions is related at the unobservable modality $\gradedt{r}{T_1}$. Applying the binary fundamental theorem yields
	$([x\mapsto v_1]t,[x\mapsto v_2]t)\in\bbrac{\gradedt{adv}{\base}}^{adv}_\cale$.
	Since $adv\le adv$, any terminating results are related at the underlying base type. The base relation relates identical canonical observations, hence if the two evaluations terminate with $[b_1]$ and $[b_2]$, then $b_1=b_2$. No equality of the complete terms is implied without an additional normalization/confluence argument.
\end{proof}
